# 小爱老师 Wi-Fi 版（Archytas）64 位 ROM 整合包

把 **Archytas（小爱老师 Wi-Fi 版）** 从「32 位原厂 ROM + 64 位内核」升级为
**完整 64 位 Android（arm64 GSI）**，含本仓库自行完成的 **vendor 分区 64 位适配**。
已在本机实机刷入并验证通过。

> `WiFi.64.zip`），所以这里用 ASCII 名发布；包内文件名仍是 `WiFi版64位整合包.zip`。

## 包里有什么

| 路径 | 内容 |
|---|---|
| `img/boot.img` | 64 位内核 boot —— Linux **4.9.117** aarch64 + Wi-Fi 板 DTB |
| `img/vendor.img` | **64 位适配版 vendor**（400 MiB ext4）★ 核心 |
| `img/system.img` | arm64 GSI —— phh `treble_arm64_bvN` Android 9 (`PQ3B.190801.002`)，**1.396 GiB，无需扩容 system 分区** |
| `stock/` | Wi-Fi 原厂 dtbo / lk / vbmeta / boot / 分区表 —— **仅供回退** |
| `flash_wifi64_fastboot.sh` | **一键刷机（fastboot，推荐）** —— 不用按键进 BROM、不用 mtkclient |
| `flash_wifi64.sh` | 一键刷机（mtkclient / BROM 路线） |

**不需要扩容任何分区**：GSI 已按原机 system 分区尺寸重打包为 1,499,136,000 B。

## vendor 适配做了什么（与 4G 包的差异）

1. **注入 `/vendor/lib64/`**（29 个 aarch64 库，11.6 MB）—— GPU(PowerVR) / EGL-GLES / gralloc·hwcomposer / ION·drm / PQ 画质栈。
   原厂 vendor 完全没有 `/vendor/lib64`（全 32 位），这是 arm64 GSI 跑不起来的根因。
2. **替换 `/lib/modules/*.ko`** 为本仓库 CI 构建的 arm64 模块（`wmt_drv` / `wmt_chrdev_wifi` / `wlan_drv_gen4m` / `bt_drv`），
   含两项修复：`scanGetCurrentEssChnlList` drain 死循环误编（`svc wifi disable` 满核卡死），以及 2c-2/2c-3 suspend workaround 默认关。
3. **`/default.prop`：`ro.zygote=zygote32` → `zygote64_32`** —— 唯一来源，且 `ro.` 属性只写一次。

基座用 **Wi-Fi 原厂 vendor（build 1754）**，与设备上的 `ro.vendor.build.fingerprint` 完全一致，避免把 4G 的 SIM/蜂窝/按键配置带进来。

> **SELinux 策略不用改**、`init.rc` 不用改、VNDK 天然匹配（`ro.vndk.version=28` ↔ GSI 自带 `vndk-28`）。
> 详见包内 `README.md`。

## 刷入（fastboot，推荐）

只需 platform-tools（[下载](https://dl.google.com/android/repository/platform-tools-latest-windows.zip)）：

```bash
FASTBOOT=/path/to/fastboot.exe bash flash_wifi64_fastboot.sh
```

脚本会：`adb reboot bootloader` → 刷 **boot / vendor / system**（**跳过 dtbo 与 vbmeta**）
→ **erase userdata + metadata + cache** → 重启。等价手动：

```bash
adb reboot bootloader
fastboot flash boot   img/boot.img
fastboot flash vendor img/vendor.img
fastboot flash system img/system.img
fastboot erase userdata
fastboot erase metadata
fastboot erase cache
fastboot reboot
```

**为什么不动 vbmeta**：本机 dm-verity 未启用（`/vendor` 是 `/dev/block/mmcblk0p30` 直挂 ext4，
非 `/dev/block/dm-X`，`ro.boot.veritymode` 为空）。动它反而有把校验重新打开的风险。
**为什么不动 dtbo**：设备上 dtbo 的前 8,388,579 字节与包内 `stock/dtbo.img` 逐字节相同。

> ⚠️ **换 system 必须双清**：原机 data 属于 Android 10（32 位），新 system 是 Android 9 arm64。
> 双清会丢应用数据与内置存储（本机实测 `/data/media/0` 约 2.5 GB），刷前请自行备份。
> 不动 preloader / lk / lk2 / nvram / nvdata / protect\*，不会硬砖；`stock/` 里有回退件。

## 实机验证结果（2026-10-06）

首启约 30 秒进桌面（首次因重建 data 稍慢）。

| 检查项 | 结果 |
|---|---|
| `ro.product.cpu.abi` | **`arm64-v8a`** |
| `ro.zygote` | **`zygote64_32`** |
| 64 位进程 | `zygote64` / `zygote` / `surfaceflinger` / `webview_zygote` 均在跑 |
| `bootanim` | `stopped`（桌面已起） |
| **分区内 lib64 vs 权威副本** | **29/29 逐字节一致**（连 fastboot 自动分块写入也无损） |
| 内核模块 | `wlan_mt6761_axi` / `wmt_chrdev_wifi` / `bt_drv` / `wmt_drv` 全部 insmod 成功 |
| Wi-Fi 开/关 | 正常，**无满核卡死** |
| SELinux | `Enforcing`；无 kernel panic；SurfaceFlinger/libEGL 崩溃已消失 |

### 修复记录：曾经卡在第一屏

首轮刷入后卡第一屏（但 adb 通、内核正常），日志 `libEGL load_driver(...libEGL_mtk.so): unknown`
→ `couldn't find an OpenGL ES implementation`。

根因：早期 ext4 读取器 `port/ext4_read.py` 解析 extent 时**丢掉 `ee_block`**，把 extent 按物理顺序
拼接，使稀疏文件的 hole 被"塌陷" —— **19/29 个 lib64 被截断**（最多短 63 KB）。截断文件的 ELF 头完好，
所以「只比对 ELF class」的旧校验全部漏过，`e2fsck` 也查不出（文件系统本身合法）。

修复：按 `ee_block` 落位 + hole 补零 + 处理 uninit extent / fast symlink；并新增
`port/elf_integrity.py` 门禁（校验 `e_phoff`/`e_shoff` 与每个 `PT_LOAD`/`PT_DYNAMIC`
的 `p_offset+p_filesz` 不越文件尾），已接入构建脚本。本 Release 的 `vendor.img` 即修复后的版本。

## 已知残留问题（不影响开机与 Wi-Fi）

- **`nvram_agent_binder` 崩溃循环**：phh GSI 的 SELinux 策略里该域无权读写 `/dev/binder`。
  属 GSI 策略与 MTK vendor 预期间的缺口，与本包改动无关（4G 包同样存在）。需用该服务时补一条 `allow`。
- `fpsgo.ko` / `met.ko` 仍是 32 位（同 4G 包），加载失败只影响调频，不影响功能。
